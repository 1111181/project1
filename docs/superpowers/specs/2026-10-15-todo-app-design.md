## 1. 目标与约束

**要解决的问题**：在手机上有一个干净、打开就能用的个人待办清单。

**使用者**：只有你一个人。自己记录、自己完成，不需要协作、不需要分享。

**成功标准**：

1. 手机上打开网址就能用，不用登录、不用等加载
2. 加任务到 3 秒内完成，勾完成 1 次点击
3. 关掉页面再打开，数据一条不少
4. 重要事项一眼能扫到
5. 拖拽排序手感跟原生 App 一样顺，不卡顿

**明确的约束**：

- 手机浏览器使用，界面按手机屏设计
- 纯静态：无构建步骤、无 npm 依赖、无后端
- 数据只存在本机浏览器，不上传任何服务器
- 单人使用，不做账号、不做多设备同步

**明确不做（YAGNI）**：

- 用户账号、登录、云同步
- 多设备实时同步
- 提醒推送 / 系统通知
- 协作、分享、评论
- 重复任务、日历视图、番茄钟

## 2. 部署形态

- 代码推到既有仓库 `github.com/1111181/project1`
- 开启 GitHub Pages，访问地址 `https://1111181.github.io/project1/`
- 纯静态托管，无服务端逻辑
- 首次加载后可离线使用（浏览器常规缓存；不做 Service Worker，见 §11）

## 4. 数据模型

存储键：`todo.v1`（单个 JSON 字符串）

```js
{
  version: 1,
  groups: [
    { id: "g_xxx", name: "工作", order: 0 }
  ],
  tasks: [
    {
      id: "t_xxx",
      groupId: "g_xxx",
      title: "交房租",
      note: "",                          // 备注，纯文本
      done: false,
      important: false,
      due: null,                         // "YYYY-MM-DD" 或 null
      subtasks: [
        { id: "s_xxx", text: "看合同", done: true }
      ],
      createdAt: 1760000000000,          // 毫秒时间戳
      completedAt: null,                 // 完成时写入，取消完成时置回 null
      order: 0                           // 组内排序，见下
    }
  ]
}
```

**排序规则**：`order` 只在**同一个 groupId 内**有意义。渲染时按 `order` 升序。拖拽结束后对该组所有任务重新编号为 `0,1,2,…`，避免小数累积误差。跨组移动时，先把任务插到目标组的指定位置，再对**两个组**分别重新编号。

**独立数据不变量**（`store.js` 负责维持，单测覆盖）：

- `task.groupId` 必须指向存在的分组；删除分组时其下任务一并删除
- 每组内 `order` 连续无重复
- `completedAt` 与 `done` 同步：`done: true` ⇔ `completedAt` 非 null
- 至少保留一个分组；删掉最后一个分组时自动建一个默认分组"未分组"

**时间注入**：`store.js` 里所有函数签名接受可选的 `now` 参数（默认取 `Date.now()`），单测传固定值，保证断言确定性。

## 5. 存储与自动保存

**写入时机（保证不丢数据）**：

1. 所有结构性改动（增删任务、勾完成、切重要、拖拽、增删分组）→ **同步立即写盘**，不防抖
2. 文本输入（标题、备注、子任务文本）→ `input` 事件 **200ms 防抖**写盘
3. 兜底：`blur` 事件、`visibilitychange` 转 `hidden`、`pagehide` 时**强制立即写盘**

第 3 条是关键。手机上切 App、锁屏、被电话打断都是 `visibilitychange`，不兜底会丢最后几个字。

**版本迁移**：`storage.js` 读盘时检查 `version`。当前只有 v1，但迁移框架先建好——读到未知的更高版本时**不覆盖、不崩溃**，提示用户"数据来自更新版本"并停在只读状态。这样以后改结构不会把数据写坏。

**读盘失败处理**：JSON 解析失败或结构不合法时，**不删除原数据**，把原始字符串备份到 `todo.v1.corrupt.<时间戳>`，用空数据启动并告知用户。宁可留一份看不懂的垃圾，也不能把用户数据静默丢掉。

## 6. 界面设计

### 6.1 首页（列表视图）

```
┌─────────────────────────────┐
│  我的待办                ⋯  │   ← 顶栏，可吸顶
├─────────────────────────────┤
│  工作                    +  │   ← 分组标题行
│  ○  写周报                  │
│ ▓●  交房租            ⠿ ▓  │   ← 重要：整行淡红底
│  ○  回邮件           2/5    │   ← 子任务进度
│  ○  体检预约       10-20    │   ← 截止日期
│                             │
│  生活                    +  │
│  ○  买牛奶                  │
│                             │
│           ⋮                 │
│  ┌───────────────────────┐  │
│  │      ＋ 添加任务       │  │   ← 固定悬浮，拇指区
│  └───────────────────────┘  │
└─────────────────────────────┘
```

**任务行元素**（从左到右）：

- 圆形复选框，点击即勾完成（触控区 44×44pt）
- `important` 为真时复选框内显示实心点
- 标题，最多两行，溢出省略号
- 右侧次要信息（只显示存在的那几项，间距 8px）：截止日期 ｜ 子任务 `2/5` ｜ 备注存在标记
- 拖拽手柄仅在拖拽态显示

**重要事项样式**：整行背景 `--color-important-bg`（Notion 红 8% 透明度），文字保持常规深色，**不加粗、不变红字、不加左边条**——按你选的方案，保持 Notion 那种克制的干净感。复选框内的实心点提供第二个识别通道，不依赖单一颜色（对色觉障碍更友好）。

**已完成任务放哪**（这里对聊天里说的做法做了一处调整）：

你选的是"勾完成后直接从列表消失"。为了避免完成后**再也看不到、也没法撤销误勾**，已完成任务放在**每个分组末尾的一行** `已完成 3 项`——平时收起只占一行、几乎不占视线，点开能看到该组所有已完成任务，并可取消完成或删除。

调整的原因：如果连撤销入口都没有，误勾一个任务就只能靠翻浏览器存储去救。多一行 20px 高的文字换来随时可撤销，这个交易划算。

**`⋯` 菜单**：导出 JSON / 导入 JSON / 清空全部数据（二次确认）。

**空状态**：一个分组都没任务时，显示引导文案 `还没有任务，点下面的按钮加一个`，而不是一片空白。

### 6.2 详情视图

从右侧滑入的全屏视图，地址变为 `#/task/<id>`：

- 顶栏：`←` 返回 + 所属分组名
- 大号标题输入框，可直接编辑，无边框，像 Notion 的页面标题
- 一行开关：`重要` · `完成`
- `截止日期`：原生 `<input type="date">`（手机系统原生选择器，体验最好）
- `分组`：下拉选择，切换后任务移到目标组末尾
- `备注`：多行 `textarea`，随内容自动增高
- `子任务`：清单，每项左侧复选框、中间文本、右侧删除；底部 `＋ 添加子任务`
- 底部只读元信息（灰色小字）：创建时间、完成时间
- 底部 `删除任务`（红色文字按钮，二次确认）

### 6.3 交互细节

| 操作 | 行为 |
|---|---|
| 点任务行（非复选框、非手柄区） | 进入详情视图 |
| 点复选框 | 勾完成 → 短暂动画 → 从列表移除 |
| 长按任务行 350ms | 进入拖拽态（轻微放大 + 阴影 + 轻微震动反馈） |
| 拖拽到列表边缘 | 自动滚动（任务多时必需） |
| 长按分组标题 350ms | 拖拽调整分组顺序 |
| 点分组标题文字 | 折叠 / 展开该组 |
| 点分组标题右侧 `+` | 在该组末尾新建任务并聚焦输入框 |
| 点 `已完成 N 项` | 展开 / 收起该组的已完成任务 |

**误触防护**：长按拖拽的触发条件是"按住 350ms 且位移小于 8px"，移动超过 8px 判定为滚动，取消长按计时。这样正常滚动列表不会被误判成拖拽。

### 6.4 视觉系统

遵循 `mobile-app-ui-design` skill 的规范：

**间距**：严格 8 点栅格，只用 4 / 8 / 12 / 16 / 24 / 32 / 48。相关元素贴近（8-12px），不相关元素拉开（24-32px）。

**颜色（60 / 30 / 10）**：

| 角色 | 亮色 | 暗色 |
|---|---|---|
| 背景（60%） | `#FFFFFF` | `#191919` |
| 次级背景 | `#F7F7F5` | `#222222` |
| 主文字（30%） | `#37352F` | `#E9E9E7` |
| 次要文字 | 主文字 60% 透明度 | 同 |
| 辅助文字/占位 | 主文字 40% 透明度 | 同 |
| 强调（10%） | `#2383E2` | `#4A9EE8` |
| 重要 | `#E03E3E` | `#FF6B6B` |
| 重要底色 | `#E03E3E` @ 8% | `#FF6B6B` @ 12% |
| 分隔线 | `#000000` @ 8% | `#FFFFFF` @ 10% |

**主题**：所有颜色走 CSS 变量，`@media (prefers-color-scheme: dark)` 覆盖一套。自动跟随系统，不做手动开关。

**字体**：系统字体栈（`-apple-system, "PingFang SC", "Microsoft YaHei", "Segoe UI", sans-serif`）。不加载网络字体——保证离线可用和秒开。最多 4 个字号、2 个字重。

| 用途 | 字号 / 字重 |
|---|---|
| 页面标题 | 22px / 600 |
| 分组标题 | 15px / 600 |
| 任务标题 | 16px / 400 |
| 次要信息 | 13px / 400 |

**形状**：卡片圆角 12px，按钮圆角 10px，复选框为圆形。**不用重阴影**——用极淡的分隔线和 1px 边框划分层次，这是 Notion 的做法。只有浮层（悬浮按钮、拖拽中的卡片）用阴影。

**触控目标**：所有可点元素至少 44×44pt 的实际触控区（视觉上可以更小，用 padding 撑开）。

**动效**：120–240ms，`ease-out` 进入、`ease-in` 离开。勾完成时复选框打勾 + 任务行高度收起 + 淡出。详情页滑入 240ms。全部动效在 `prefers-reduced-motion: reduce` 下关闭。

## 7. 拖拽实现

原生 Pointer Events，不引第三方库（保持零依赖）。

**为什么不用 HTML5 的 Drag and Drop API**：它在移动端浏览器上**根本不触发**，只能用于桌面。手机上必须用 Pointer Events（`pointerdown` / `pointermove` / `pointerup`）自己实现。

**做法**：

1. `pointerdown` 记录起点，启动 350ms 长按计时器
2. 计时器到点且位移 < 8px → 进入拖拽态，给原元素加 `.dragging`（提升 `z-index`、轻微放大、加阴影）
3. `pointermove` 时用 `transform: translateY()` 移动元素（**只动 transform，不动 top/left**，保证不触发重排、不掉帧），同时计算落点索引，其他任务行让位
4. 指针接近容器上下边缘 60px 内时按距离比例自动滚动
5. `pointerup` 提交新顺序，重排 `order`，写盘

**关键细节**：

- 元素上设 `touch-action: none`，否则浏览器会把滑动解释成页面滚动
- `pointerdown` 后调用 `setPointerCapture`，手指移出元素也能继续收到事件
- 拖拽中用 `requestAnimationFrame` 节流，避免每个 `pointermove` 都写 DOM

## 8. 数据保险（导入 / 导出）

`⋯` 菜单提供：

- **导出 JSON**：把当前数据下载成 `todo-backup-YYYY-MM-DD.json`
- **导入 JSON**：读文件 → 校验结构 → 二次确认 → 整体替换

**为什么必须有**：数据只存在浏览器里，用户清一下浏览器数据就全没了，换手机也带不过去。这是唯一的安全网，成本很低。

导入时校验：必须是合法 JSON、`version` 已知、`groups` / `tasks` 是数组、每个 task 的 `groupId` 能对上（对不上的归入"未分组"，不丢数据）。校验失败则拒绝导入并说明原因，绝不半途写入。

## 9. 测试策略

**单元测试**（`node --test tests/store.test.mjs`，无依赖，node 内置测试框架）覆盖 `store.js` 的纯函数：

- 新增 / 删除 / 修改任务
- 切换完成状态 → `completedAt` 正确写入与清空
- 切换重要状态
- 组内重排 → `order` 连续无重复
- 跨组移动 → 两个组的 `order` 都正确重排
- 新增 / 重命名 / 删除分组；删除分组时其任务一并删除
- 删除最后一个分组 → 自动创建默认分组
- 子任务增删改
- 导入校验：合法数据通过、各类非法数据被拒绝
- 版本迁移：读到 v1 正常、读到未知高版本不崩溃
- 时间注入：传固定 `now`，断言 `createdAt` / `completedAt`

**手工验收清单**（浏览器里跑，我会逐条实测并如实报告结果）：

1. 加任务、勾完成、标重要 → 刷新页面数据仍在
2. 手机尺寸下拖拽排序，组内跨组都试
3. 拖拽时滚动列表不误触发拖拽
4. 进详情页 → 按浏览器返回键 → 回到列表且滚动位置保留
5. 备注输入到一半直接切走 App → 回来内容还在
6. 导出 → 清空 → 导入 → 数据完全一致
7. 亮 / 暗主题下都检查对比度和红色可辨识度
8. 断网刷新 → 页面仍能打开

**不做的测试**：不做端到端自动化、不做视觉回归。这个规模的应用，手工清单比搭一套 E2E 更划算。

## 10. 风险与取舍

| 风险 | 应对 |
|---|---|
| 数据只在浏览器里，清缓存即丢 | 导出/导入备份（§8）；文档里写明 |
| 手机浏览器地址栏占位、`100vh` 不准 | 用 `100dvh` + `env(safe-area-inset-*)` 处理刘海和底部横条 |
| iOS Safari 的 localStorage 在隐私模式下受限 | 启动时探测试写，失败则顶部显示提示条，不做静默失败 |
| 拖拽手感在不同机型上不一致 | 只用 Pointer Events + transform，不依赖各家的私有行为；真机实测 |
| `file://` 打开会因 ES modules 报错 | 文档写明必须用 http 服务器预览；Pages 上无此问题 |

## 11. 明确不做 Service Worker

PWA / Service Worker 上一轮已确认排除。GitHub Pages 是 HTTPS，浏览器常规缓存已能支撑基本离线使用。引入 Service Worker 会带来缓存版本管理的复杂度（用户看到旧版本的经典坑），收益不匹配。**如果以后想要离线更可靠或加到主屏幕，这是一个独立的后续任务。**
