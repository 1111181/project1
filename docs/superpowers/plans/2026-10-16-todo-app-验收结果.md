## 3. 必须在真机上确认的（本地无论如何测不出来）

**为什么**：无头浏览器没有触摸屏、没有主屏幕、没有刘海、没有系统手势条。合成事件能验证代码逻辑，验证不了「手指按下去是什么感觉」。

请在手机浏览器打开 `https://1111181.github.io/project1/`（部署之后）逐条试：

| 要确认的事 | 具体怎么做 | 期望 |
|---|---|---|
| 长按手感 | 按住一条任务约 0.5 秒再拖 | 元素浮起（有阴影），原位置留一个虚线框 |
| **滚动不被拖拽抢走** | 单指在任务行上快速上下滑 | 页面正常滚动，**绝不**触发拖拽。这一条是误触防护的核心 |
| 拖拽时不再滚动 | 长按进入拖拽态后，手指上下移动 | 页面不跟着滚；只有手指贴近上下边缘时列表才自动滚 |
| 跨分组拖拽 | 把一条任务拖到另一个分组中间松手 | 任务进目标组，刷新后顺序仍是新的 |
| 切 App 不丢字 | 在备注里输入一半，切到别的 App 再切回来 | 内容还在 |
| 锁屏不丢字 | 备注输入一半直接锁屏，解锁后回到浏览器 | 内容还在 |
| 加到主屏幕 | iOS：分享 → 添加到主屏幕；安卓 Chrome：菜单 → 添加到主屏幕 | 主屏幕出现蓝色圆角勾图标 |
| 全屏打开 | 从主屏幕图标打开 | **没有地址栏**、没有底部工具栏 |
| 刘海与手势条 | 在刘海屏/全面屏手机上全屏看 | 顶部内容不被刘海压住、底部悬浮按钮不被系统手势条盖住 |
| 暗色主题自动跟随 | 把系统切成深色，重新打开 | 背景变深、文字变浅，不需要手动设置 |

**如果哪一条不对**，把现象记下来（最好截个图），回来告诉我，我按现象定位。

## 4. 断网刷新：本地为什么测不了

实测结果：把本地服务器停掉之后加载页面，得到 `net::ERR_CONNECTION_REFUSED`。

原因有两层，都不是缺陷：

1. **本地开发服务器故意发 `Cache-Control: no-store`**（`tools/serve.mjs`，为了让改完代码刷新就能看到效果）。什么都不缓存，断网自然什么都没有。
2. **按设计不引入 Service Worker**（设计文档 §11 明确放弃）。没有 SW 就没有「保证离线」这回事，离线只能靠浏览器的常规 HTTP 缓存。

**GitHub Pages 上的表现会不同**：Pages 给静态资源发的缓存头是允许缓存的，所以「断网后短时间内刷新」**可能**能打开。但这是浏览器缓存说了算，不保证——缓存被清、或者很久没访问，就会白屏。

**这一条在设计文档 §11 里已经作为已知代价写明了**：离线不保证，打不开不算 bug。数据不受影响——数据在 `localStorage`，不在 HTTP 缓存里，两者是分开的。

想验证的话：手机打开 Pages 网址 → 开飞行模式 → 下拉刷新。能打开就是缓存命中，打不开就是没命中，两种情况都符合预期。

**哪天真觉得离线重要**：补一个 `sw.js` 就行，manifest 和图标已经就位，是一个独立的小任务。

## 6. 本次实施中，从计划之外发现并修掉的问题

记录在案，供以后回看。

| 问题 | 怎么发现的 | 处理 |
|---|---|---|
| **回车加完一条任务后输入行消失，无法连续录入** | list-probe 的 C2/C3 断言失败并崩在 `Cannot set properties of null` | `render()` 开头清空 `root` 时会移除持有焦点的输入框并**同步触发 blur**，被当成「用户失焦」。blur 处理器补上 `painting` 守卫（分组重命名有同样毛病，一并修了） |
| **拖拽落点计算无法单测** | 实施 Task 11 时发现这段逻辑埋在 DOM 测量里 | 抽成纯函数 `dropIndexFor` 并补 7 个单测 |
| **本机没有 python** | 计划假设用 `python -m http.server`，实际那只是 Windows 商店的占位符 | 新增零依赖的 `tools/serve.mjs` |
| **`touch-action: none` 会让列表滑不动** | 设计评审时逐条核对 spec §7 | 改为 `manipulation` + 拖拽期间拦截 `touchmove`（探针 22/23 直接断言了计算值） |
