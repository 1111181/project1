## 4. 搜索并安装 skill 的过程（含一个坑）

### 搜索

用 `npx skills find` 搜了多轮（"mobile app ui design"、"notion style minimal ui"、"drag and drop interaction"、"vanilla javascript web app"）。

### 安装结果

| skill | 安装数 | 结果 |
|---|---|---|
| `designed-by-ai/skills@design-mobile-apps` | 819K | 装上了，**但发现是坑** |
| `uizze.sh@ui-taste` | 583K | **装不上**——它不是 GitHub 仓库，是 skills.sh 自托管的，CLI 无法 clone |
| `leonxlnx/taste-skill@design-taste-frontend` | 612K | 作为 ui-taste 的替代装上，**但用途不符** |
| `ceorkm/mobile-app-ui-design@mobile-app-ui-design` | 10.9K | ✅ **这个才是有用的** |

### 两个坑的详情

**`design-mobile-apps` 是付费服务的客户端。** 读 SKILL.md 才发现它不是设计指导，而是 `sleek.design` 的 REST API 客户端：需要 `SLEEK_API_KEY`（device flow 授权），免费账号只有一次性试用额度约够跑一次设计，持续使用需订阅 Pro。安装数 819K 但内容与预期完全不符。**教训：安装量高不等于符合用途，用之前必须读 SKILL.md。**

**`design-taste-frontend` 用途不符。** 它的 description 里明确写着 "Not for dashboards or app screens"，只做营销落地页 / 作品集。免费且本地，但对这个待办应用没用。

### 真正采用的那个

`mobile-app-ui-design`（ceorkm，10.9K 安装）：免费、本地、无 API。提供 8 点栅格系统、60/30/10 配色法则、拇指区放置、44pt 触控目标、空状态规范、字体数量上限（4 字号 / 2 字重）、阴影规范、反模式清单。设计文档 §6.4 的视觉系统就是按它写的。

### 网络问题的修复

`npx skills add` 报 `Failed to connect to github.com:443`，但 `curl https://github.com` 返回 200。根因是 git 走了 Windows schannel 的证书吊销检查，在国内网络下报 `CRYPT_E_NO_REVOCATION_CHECK (0x80092012)`。

修复：`git config --global http.schannelCheckRevoke false`

**这是全局 git 配置改动**，如果以后 git 出现证书相关异常，可以回退。
